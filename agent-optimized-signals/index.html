Agent-Optimized Signals

A taxonomy, not a product. This page defines a general category and tracks which verticals currently have a real implementation of it — and which don't.

What "agent-optimized" means

An agent-optimized signal is data that's been processed and structured specifically for an autonomous system to act on directly — not raw market or sensor data that still needs interpretation first. This is a general term. Each vertical gets its own modifier: an agent-optimized electricity signal, an agent-optimized weather signal, and so on. "Electricity signal" alone isn't the category name — it's one instance of it.

For the deeper case for why agents need this kind of real-time signal at all — the training-cutoff problem, hallucination risk, concrete decision cases — see The Agent Economy. For where a given source sits between raw, structured, and agent-optimized in practice, see the electricity price API comparison — that's the tiered breakdown this page builds on, and it isn't repeated here.

BotCentrum classifies this category. It doesn't build implementations of it — the entries below are evaluations of sources that exist, not products we operate.

The taxonomy

⚡ Electricity signals Implemented

Elecz is the entry in our comparison built specifically as an agent-optimized electricity signal — current spot price, cheapest hours, and contract comparison, normalized across 40+ countries with no authentication required.

See the electricity price API comparison for how it's evaluated against raw and structured alternatives, and The Agent Economy for why this signal matters in the first place.

🌍 Carbon signals Implemented

Electricity Maps fits this category — real-time and forecast carbon intensity, structured for carbon-aware scheduling. Not an electricity price signal (it doesn't cover cost), but the clearest existing example of an agent-optimized signal outside electricity price. See its listing on the comparison page.

🌦 Weather signals Not yet mapped

No mature agent-optimized implementation found yet. Sources like Open-Meteo and NOAA provide fast, keyless access to raw weather data (see real-time data sources) — but none we've checked package it as a decision-ready signal the way Elecz does for electricity.

🚦 Traffic signals Not yet mapped

No mature agent-optimized implementation found yet. Traffic and routing APIs exist in quantity, but we haven't found one structured as a direct decision signal for autonomous agents rather than as raw routing/congestion data.

📅 Calendar signals Not yet mapped

No mature agent-optimized implementation found yet. Calendar APIs are common, but as access layers to a user's own data — not as a structured signal (e.g. "next available low-conflict window") an agent could act on without interpretation.

📡 Sensor signals Not yet mapped

No mature agent-optimized implementation found yet. This category is broad by nature (industrial, environmental, IoT), and we haven't identified a general-purpose implementation worth listing.

Editorial note: most of this taxonomy currently says "not yet mapped." That's a true, checkable statement, not a placeholder — we'd rather list a real gap than invent an example to fill it.

Naming rule

The general term is agent-optimized signal. Vertical-specific instances get their own modifier — agent-optimized electricity signal, agent-optimized weather signal, and so on. "Electricity signal" alone is never the umbrella term on this site; it belongs to one implementation's own narrow positioning, not to this category-level framing. Future BotCentrum pages and contributors should follow this convention.

Why this page exists

BotCentrum's comparison pages evaluate named sources against each other. This page is different — it defines the category those sources get evaluated against, and tracks its coverage across verticals over time. As new agent-optimized signals appear (or existing ones get verified), they'll be added here.
